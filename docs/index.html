Quick guide to Relay's development source. The API and protocol reference owns the full contract; the API may change.

Home

Versions and changes

0.3.0 (current private development source; unreleased). Adds RR7 primitive unreliable frames, up to 64 endpoints and readiness listeners, Color3, tagged unions, maps, 22 bounded Roblox value shapes, opt-in RR8 ordered unreliable events, and bounded Instance references for reliable immediate events. See upgrade compatibility. Published v0.2.0 remains the installable release.

0.1.0 (earlier repository baseline). Includes typed reliable and unreliable events, bounded schemas, and client ingress admission. See the baseline source.

Starting with v0.2.0, each published release tag preserves its API reference; read the published v0.2.0 reference for the separately pinned release. This guide describes private development source version 0.3.0 and may differ from that release. Its quick-start scripts match the current source example.

Tooling includes receive-callback profiling, including the bounded RR3 composite case. See the receive profiling guide.

Security, performance, and accessibility

  • Security: Relay bounds its ingress work and rejects malformed payloads before handlers. Schemas do not authorize gameplay; your game owns permission checks.
  • Performance: Reliable primitive-only events use native Roblox tuples; unreliable and composite events use bounded buffers. Audience sends encode once. Measure costs in your workload using the benchmark tools.
  • Accessibility: Game code owns accessible controls and feedback. These docs use keyboard navigation, semantic headings, visible focus, and readable code blocks.

General

Relay is a standalone Roblox library for defining event names, directions, and payload fields once in a shared ModuleScript. The same definition gives the server and client matching event handles. Delivery is reliable by default, with optional unreliable events. Relay has no runtime dependencies.

Setup

Install the published release

Download the v0.2.0 model and import it into ReplicatedStorage. Use its published API reference and reliable-events example. The matching v0.2.0 source ZIP is available for source-based use.

Build from development source

These instructions describe the private, unreleased 0.3.0 development API. Build from a source checkout that matches these docs; the earlier 0.1.0 baseline does not include all APIs shown here. The Wally package is private. With Rokit installed, run from the repository root:

rokit install
rojo build default.project.json --output relay.rbxmx

Import relay.rbxmx into ReplicatedStorage. In Studio, set Workspace.UseNewLuauTypeSolver to Enabled and use --!strict in consumer scripts. See the full setup and working example.

Object-producing operations that report errors return (value, nil) or (nil, error); boolean operations return (true, nil) or (false, error). Errors contain code and message, so use assert(value, err and err.message).

Types

GroupSchema types
Primitiveboolean, string, u8, u16, u32, i8, i16, i32
Numeric and Roblox valuesf32 with finite bounds; Vector2F32, Vector3F32, CFrame, Color3, and bounded native Roblox values including UDim, sequences, Font, and DateTime
Compositestruct, bounded taggedUnion, bounded array, bounded map, enum, optional, and bounded set
Instance referencesInstance(className) for the closed class list, in reliable immediate event payloads

String byte limits and composite sizes are declared in the schema. Instance references are limited to reliable immediate events and a server-owned scope root; user buffers, arbitrary map shapes, and recursive schemas are unsupported. See the Instance reference contract.

Exported Luau types include Definition<S>, ServerSession<S>, ClientSession<S>, RelayError, Connection, and RequestResult<T>. Keep definitions and sessions inferred; annotating them broadly as DefinitionSpec loses payload types. See the schema reference.

Events

Each event has a stable ID, a direction, and ordered fields. Omit delivery for reliable transport. Unreliable events can be dropped or reordered. Opt-in OrderedUnreliable discards stale snapshots after the first accepted frame; see the ordering contract.

Quick start

These three scripts are the checked reliable-events example. They define client-to-server Input and server-to-client State; the server shows where an application may send State after client startup. Add the ModuleScript and scripts to the locations shown.

Definition: ModuleScript in ReplicatedStorage

--!strict
-- Place this ModuleScript in ReplicatedStorage alongside Relay.
local Relay = require(game:GetService("ReplicatedStorage").Relay)
local s = Relay.schema

local definition, definitionError = Relay.define({
	name = "Gameplay",
	version = 1,
	events = {
		Input = s.clientToServer(1, s.fields(
			{ sequence = s.u32() },
			{ enabled = s.boolean() }
		)),
		State = s.serverToClient(2, s.fields(
			{ sequence = s.u32() },
			{ health = s.u8(nil, 100) }
		)),
	},
})

return assert(definition, definitionError and definitionError.message)

Main.server: Script in ServerScriptService

--!strict
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Relay = require(ReplicatedStorage.Relay)
local Events = require(ReplicatedStorage.Definition)

local serverResult, createServerError = Relay.createServer(Events, {
	inboundRate = {
		perPlayer = { capacity = 120, refillPerSecond = 60 },
		aggregate = { capacity = 960, refillPerSecond = 480 },
	},
})
local server = assert(serverResult, createServerError and createServerError.message)

local connectionResult, connectError = server.events.Input:Connect(function(player, sequence, enabled)
	-- Validate permissions, cooldowns and authoritative game state here.
	-- A structurally valid input does not authorize a gameplay effect.
end)
local connection = assert(connectionResult, connectError and connectError.message)
local started, startError = server:Start()
assert(started, startError and startError.message)

-- Once your application has established client startup:
-- local sent, sendError = server.events.State:Send(player, sequence, health)
-- assert(sent, sendError and sendError.message)
-- local broadcast, broadcastError = server.events.State:Broadcast(sequence, health)
-- assert(broadcast, broadcastError and broadcastError.message)

script.Destroying:Connect(function()
	connection:Disconnect()
	server:Destroy()
end)

Main.client: LocalScript in StarterPlayerScripts

--!strict
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Relay = require(ReplicatedStorage:WaitForChild("Relay"))
local Events = require(ReplicatedStorage:WaitForChild("Definition"))

local clientResult, createClientError = Relay.createClient(Events, { startupTimeoutSeconds = 10 })
local client = assert(clientResult, createClientError and createClientError.message)
local connectionResult, connectError = client.events.State:Connect(function(sequence, health)
	-- Apply server-authored state to your client presentation here.
end)
local connection = assert(connectionResult, connectError and connectError.message)

script.Destroying:Connect(function()
	connection:Disconnect()
	client:Destroy()
end)

local started, startError = client:Start()
if not started then
	connection:Disconnect()
	client:Destroy()
	if startError and startError.code == "DefinitionMismatch" then
		warn("Relay definitions differ; reconnect with matching server and client game builds")
		return
	end
	error(startError and startError.message or "Relay client startup failed", 0)
end
local sent, sendError = client.events.Input:Send(1, true)
assert(sent, sendError and sendError.message)

A successful Send reports a local transport handoff, not receipt or handler completion.

Methods by direction

DirectionSenderReceiver
Client → serverClient: event:Send(...)Server: event:Connect(handler) or event:Once(handler)
Server → clientServer: event:Send(player, ...), :Broadcast(...), :SendTo(...), :SendExcept(...)Client: event:Connect(handler) or event:Once(handler)

Server and client definitions must match. For the current limits and delivery details, read the protocol and abuse limits.

Functions

Relay.VERSION
Current library version.
Relay.schema
Schema constructors such as field, ordered, and u32; schema.compose(...) combines event maps.
Relay.define(spec)
Validate and freeze a shared definition.
Relay.inspect(definition)
Report compiled schema details and limits.
Relay.createServer(definition, options)
Create a server session with required inboundRate limits.
Relay.createClient(definition, options)
Create a client session with a startup timeout.

Sessions provide :Start(), :Destroy(), and :GetDiagnostics(). Sessions with queue-enabled events can use :CreateBatch(...); sessions with state-queued events can also use :CreateState(...). Clients provide :RefreshReadiness(...) when readiness is enabled. With readiness enabled, each server-to-client event handle provides server.events.Name:GetReadyPlayers().

Request definitions add server.requests.Name:Connect(handler) and client.requests.Name:Request(timeoutSeconds, ...). The returned pending handle supports :Await() and :Cancel(). See schema composition, requests, readiness, FIFO batches, and state queues.

Examples: combat-inventory shows schema composition and requests; state-snapshots shows queued state.

Cleanup

  • Call connection:Disconnect() to release a listener. Disconnect is idempotent, and one receiver may be connected per endpoint.
  • Call session:Destroy() to end a session and release its state. Session destruction is idempotent.
  • pending:Cancel() cancels the local wait; it does not undo server work. Cancel an open batch or destroy a state queue when it is no longer needed.
  • Relay does not automatically retry or reconnect after transport loss. Create a new session to restart.

Run locally

The quick Studio benchmark is a local diagnostic, not a blanket performance claim. Run it from the repository root with the tools pinned in rokit.toml.

lune run benchmarks/quick/build.luau

Open .tmp/relay-quick.rbxlx in Studio and press F5 or Play with one client. The default run compares Native RemoteEvent with the current local Relay source, including uncommitted changes.

Use --category all for the five matched payload categories. Select one library with --adapters relay-reliable, a comparison with --adapters relay-reliable,quicknet, or all nine with --all. The complete selection runs in one Play session and can repeat through Session.run(). This build uses already-installed pinned dependencies; follow the adapter guide for first-time preparation.

lune run benchmarks/quick/build.luau --all --category all

Receive profiling is available with --profile-receive; it measures elapsed work inside the receive callback, including Relay validation and dispatch. Server-side client-to-server cases also include admission, and the bounded RR3 composite case includes decoding. It excludes network transit and engine work before callback entry, includes instrumentation overhead, and is not isolated CPU time. The profiling guide covers case selection and limits.

lune run benchmarks/quick/build.luau --profile-receive

Keep correctness checks separate from timing and compare equivalent semantics with pinned dependencies. See the quick benchmark guide and full benchmark notes for their workflows and limits.
