Relay 0.3.0 benchmarks

Seven Roblox Studio workloads with Relay, native RemoteEvent, and eight other networking libraries.

On this page

Results by workload

Relay and native RemoteEvent had similar sender frame times on steady sends. Median send-call time for steady State was 27 to 29 µs in Relay and about 14 µs in native. Tiny request/echo medians were about 8.3 ms for both. Relay's p95 was 12.9 ms in both passes. Native measured 9.5 and 11.1 ms.

Each pair shows pass 1 / pass 2. The lowest median time earns rank 1 in each pass, with separate ranks for native broadcast and adapter fan-out. Rankings use full precision. Exact ties share a rank. Rows follow the ranks from pass 1.

How we measured

On November 23, 2026, we tested Relay source 7a59b80 in Studio 0.748.0.7481526 on one Windows host. We ran each library twice per workload. The second pass reversed the first pass's order. All 140 sessions passed their checks. Each session started fresh and measured 30 windows after warmup.

Tiny carries a sequence number and a boolean. State carries a sequence number, an entity ID, a 3D position, yaw, and health. The first three tests send from client to server. Steady sends one event per frame and burst sends four.

Frame time is the interval between sender frames. Sender FPS is 1,000 divided by the median frame time in milliseconds. At least 95% of samples were at or below the p95 time. Send-call time measures how long the send method takes to return. Deferred transport and receiver work fall outside that window. The request/echo test times a Tiny event going to the server and back. Wire bandwidth was unavailable.

The tables group libraries by how they broadcast. Native broadcast uses one call for all clients. Adapter fan-out makes a separate call for each client. Small differences can change the order. For example, native's eight-client median frame interval moved 6.1% between passes. Suphi-Packet fell outside the test because its sender buffering could not be verified against the one-frame limit.
