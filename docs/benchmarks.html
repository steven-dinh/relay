How to read FPS, scale, and bandwidth

Rows sort by sender FPS as a local diagnostic. FPS is the median of four round values, each calculated as 1 / mean sender frame interval. Scale compares with Native in the same case and broadcast mode. N/A means there is no Native baseline.

Send KB/s is engine-wide traffic in kilobytes per second, including background and control traffic. It does not measure attributable wire bytes. Broadcast modes remain separate. Small differences in these results do not establish repeatable wins.

Historical library comparisons

The September 7 to 11, 2026 cohort has 76 valid selected runs across seven workload/topology selections and nine eligible adapters. These are the latest completed valid runs for each adapter and compatible group. Relay rows use measured 0.1.0 revisions. Native State steady C2S was not measured.

Each row is one session with 30 persistent windows. Frame values are sender frame intervals, not per-send or serialization time. Only RTT measures request and echo latency. Ranks use unrounded medians within each compatible workload, Studio version, and broadcast mode. Displayed values are rounded to three decimals. Higher derived sender FPS ranks first. Lower RTT ranks first. Exact ties share rank. One-session differences do not establish repeatable wins.

How to read canonical FPS and timings

* Sender FPS is 1000 divided by the displayed median frame interval in ms. It is not average or rendered FPS. Scale is the Native median divided by the library median in the same selection. N/A means there is no matching baseline. Rounded frame intervals make derived values approximate. Send KB/s was unmeasured. At least 95% of frame intervals were at or below p95, a secondary timing diagnostic.

Run a local benchmark

Run the quick Studio benchmark from the repository root with the tools pinned in rokit.toml.

lune run benchmarks/quick/build.luau

Open .tmp/relay-quick.rbxlx in Studio and press F5 or Play with one client. The default run compares Native RemoteEvent with the current local Relay source, including uncommitted changes.

--category all selects the five matched payload categories. Use --adapters relay-reliable for one library or --adapters relay-reliable,quicknet to compare two. Add --all to run all ten libraries. A selection runs in one Play session and can repeat with Session.run(). Install pinned dependencies by following the adapter guide.

lune run benchmarks/quick/build.luau --all --category all

Run --profile-receive to measure elapsed time inside the receive callback, including Relay validation and dispatch. Server-side client-to-server cases also include admission. The bounded RR3 composite case includes decoding. Measurements exclude network transit and engine work before callback entry. Instrumentation adds overhead, so this is not isolated CPU time. The profiling guide covers case selection and limits.

lune run benchmarks/quick/build.luau --profile-receive

Run correctness checks outside timed regions. Compare equivalent workloads with pinned dependencies. See the quick benchmark guide and full benchmark notes.
