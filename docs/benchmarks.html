Relay 0.3.0 and other libraries

November 23, 2026. Source 7a59b80, Studio 0.748.0.7481526. All 140 sessions passed their checks. Each pass measured ten adapters across seven selections on one Windows host. The second pass reversed the first pass’s order. Each session started fresh and measured 30 windows after warmup.

Relay’s steady client-to-server median frame times were close to native RemoteEvent. For Tiny request/echo, median latency was about 8.3 ms for both. Relay’s p95 was 12.9 ms in both passes. Native measured 9.5 and 11.1 ms.

How to read these results

Timing and FPS cells show pass 1 / pass 2. Rows follow the first pass’s median within each broadcast mode. Native broadcast uses a native broadcast call. Adapter fan-out sends separately to each recipient. The benchmark groups these modes separately across all seven selections.

Sender FPS is 1,000 divided by the median sender frame interval in milliseconds. The send-call median measures elapsed time from public submission to return and excludes deferred transport and receiver work. The round-trip test measures Tiny event request/echo. Lower time is better. Wire bandwidth was unavailable.

Two sessions per selection show local variation. For example, native’s median sender frame interval for eight-client broadcast changed 6.1% between passes. Suphi-Packet falls outside this cohort because its sender buffering could not be verified against the one-frame limit.

How to read FPS, scale, and bandwidth

Rows sort by sender FPS for local diagnosis. FPS is the median of four round values. Each round's FPS is 1 divided by its mean sender frame interval. Scale compares with Native in the same case and broadcast mode. N/A means there is no Native baseline.

Send KB/s is engine-wide traffic in kilobytes per second, including background and control traffic. It does not measure attributable wire bytes. Broadcast modes remain separate. Small differences in these results do not establish repeatable wins.

Historical library comparisons

The September 7 to 11, 2026 cohort has 76 valid selected runs across seven workload/topology selections and nine eligible adapters. These are the latest completed valid runs for each adapter and compatible group. Relay rows use measured 0.1.0 revisions. Native State steady C2S was not measured.

Each row is one session with 30 persistent windows. Frame values are sender frame intervals, not per-send or serialization time. Only RTT measures request and echo latency. Ranks use unrounded medians within each compatible workload, Studio version and broadcast mode. Values are displayed to three decimals. Higher derived sender FPS ranks first; lower RTT ranks first. Exact ties share rank. Differences from one session do not establish repeatable wins.

How to read canonical FPS and timings

* Sender FPS is 1000 divided by the displayed median frame interval in ms. It is not average or rendered FPS. Scale is the Native median divided by the library median in the same selection. N/A means there is no matching baseline. Rounded frame intervals make derived values approximate. Send KB/s was not measured. At least 95% of frame intervals were at or below p95, a secondary timing diagnostic.

Run a local benchmark

Run the quick Studio benchmark from the repository root with the tools pinned in rokit.toml.

lune run benchmarks/quick/build.luau

Open .tmp/relay-quick.rbxlx in Studio and press F5 or Play with one client. The default run compares Native RemoteEvent with the current local Relay source, including uncommitted changes.

Use --category all to select the five matched payload categories. Set --adapters relay-reliable to run one library, or --adapters relay-reliable,quicknet to compare two. Add --all to run all ten libraries. Each selection runs in one Play session and can be repeated with Session.run(). Install pinned dependencies by following the adapter guide.

lune run benchmarks/quick/build.luau --all --category all

Run --profile-receive to measure elapsed time inside the receive callback, including Relay validation and dispatch. Server-side client-to-server cases also include admission. The bounded RR3 composite case includes decoding. These measurements exclude network transit and engine work before callback entry. Instrumentation adds overhead, so the results are not isolated CPU time. The profiling guide covers case selection and limits.

lune run benchmarks/quick/build.luau --profile-receive

Run correctness checks outside timed regions. Compare equivalent workloads with pinned dependencies. See the quick benchmark guide and full benchmark notes.
