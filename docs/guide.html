Send and receive

Each event needs a stable ID, a direction and fields in the order its handler receives them. The client and server must use the same definition. Senders call Send. Receivers connect a handler or use Once for the next event. A successful send means Relay handed off the message locally. It does not confirm that the receiver got it.

Client to server
Send with event:Send(...). The server handler receives the player first, followed by the fields.
Server to client
Send with event:Send(player, ...). The client handler receives the fields.

The server can target an audience with Broadcast, SendTo or SendExcept. Relay encodes the audience's payload once.

With listener readiness enabled, clients can call RefreshReadiness. The server can check readiness for an event with GetReadyPlayers. Listener readiness

Delivery and permissions

Events are reliable by default. Unreliable updates may arrive out of order or be lost. Choose OrderedUnreliable when a late snapshot should be discarded after a newer one arrives. Ordered delivery

Relay validates client payloads before calling a handler. In the handler, check the player's permissions before changing game state. Your game controls what players can do and provides any feedback they need. Protocol and abuse limits

Choose field types

Declare fields with schema.fields in the order the handler receives them. Let Luau infer the definition and session types. Annotating with DefinitionSpec hides the individual payload types.

Numbers and flags
Use booleans, signed or unsigned integers of 8, 16, 24 or 32 bits, and bounded f16, f24, f32 or f64 values. Quantized scalars still have the Luau type number. Numeric formats
Roblox values
Send vectors, CFrames and Color3, plus supported native types such as UDim, sequences, Font and DateTime. Quantized vectors keep their native type. Compact CFrames have separate position and rotation error bounds. Vector and CFrame precision · Native types
Strings and collections
Set exact lengths or minimum and maximum bounds for strings, buffers and collections. Build records from structs, arrays, maps, sets, enums, optional fields or tagged unions. Recursive schemas, unbounded buffers and unbounded maps are unsupported. Composable shapes · Bit packing
Instance references
Declare an allowed class with schema.Instance(className). The server controls the permitted scope. Each complete frame can carry up to 16 references total across immediate, queued, unreliable, ordered or RPC payloads. Instance rules

The module exports Definition<S>, ServerSession<S>, ClientSession<S>, RelayError, Connection and RequestResult<T>. Event schemas

Batch or replace updates

Call Send for a single event. Reliable events with only primitive fields use native Roblox tuples by default. Unreliable and composite events use bounded buffers.

Keep every queued event
Use CreateBatch for a single flush. Use CreateBatcher to send repeated batches on queue-enabled events. A client's CreatePacedBatcher can split packets within limits and flush manually or on a timer. FIFO batches · Client pacing
Keep the latest value
Use CreateState when a newer value with the same key should replace an unsent one. A server can defer updates for a captured audience under its outbound byte budget. Recipients can make progress independently. State queues · Outbound budgets
Send to everyone
For the current roster, CreateBroadcastBatcher sends a shared packet on each channel with queued events. CreateBroadcastState shares the latest unsent values. Broadcast batches · Broadcast state
Stream a moving object
Eligible ordered server events can set a send rate, skip unchanged samples and send a keepalive. Streams include server timestamps. Client events can declare timestampWindow for a server-time field that Relay fills when the event is submitted. Scheduled streams · Client timestamps

The state snapshots example uses a fixed audience and shows how the queue behaves when it fills.

Request a reply

Declare the request fields and response shape together. For a client request, connect the handler with server.requests.Name:Connect(handler). The client calls client.requests.Name:Request(timeoutSeconds, ...), then uses Await() on the returned handle. Cancel() ends the local wait, but work already underway on the server can still finish.

The combat and inventory example combines event maps and requests an inventory response. Request API

Session API

Relay.VERSION
The library's version.
Relay.schema
Construct field types and event definitions. Combine event maps with schema.compose(...).
Relay.define(spec)
Validate and freeze a shared definition.
Relay.inspect(definition)
Read a compiled schema and its limits.
Relay.createServer(definition, options)
Create the server session with its required inboundRate limits.
Relay.createClient(definition, options)
Create the client session with a startup timeout.

Connect listeners before calling Start(). Fallible calls return a value or success flag, plus an error. When a call fails, read the error's code and message.

Use GetDiagnostics() to inspect a session. Optional traffic counters and bounded refusal reports do not change the messages sent. Traffic and refusal reports

End a session

Each endpoint accepts one listener. Call connection:Disconnect() when it no longer needs to receive events. Cancel an open batch or destroy a state queue when finished.

Call session:Destroy() to release the session. It is safe to repeat Disconnect() or Destroy(). To reconnect after transport loss, create a new session.
