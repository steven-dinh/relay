API guide

Choose how an update should reach a player. Use the full reference for signatures, field limits and error codes.

Send and receive

Give each event a stable ID, a direction and an ordered list of fields. Both sides require the same definition. The sender gets a Send method. The receiver connects a handler or uses Once for the next event. A successful send means Relay handed off the message locally. The receiver may still miss it.

DirectionSendReceive
Client to serverevent:Send(...)The server handler receives the player first, then the fields.
Server to clientevent:Send(player, ...)The client handler receives the fields.

To reach more players, the server can use Broadcast, SendTo or SendExcept. It encodes the audience's payload once. When listener readiness is enabled, clients can call RefreshReadiness and the server can query GetReadyPlayers for an event. Listener readiness

Delivery and permissions

Delivery is reliable by default. Unreliable updates can arrive out of order or go missing. Choose OrderedUnreliable when a late snapshot should be discarded after a newer one arrives. Ordered delivery

Relay checks client payloads before it calls a handler. In the handler, check what the player may do before changing game state. Your game also supplies its players' controls and feedback. Protocol and abuse limits

Choose field types

Use schema.fields to declare fields in the order the handler receives them. Let Luau infer the resulting definition and session types. An annotation such as DefinitionSpec loses the individual payload types.

Numbers and flags
Use booleans, signed or unsigned 8-, 16-, 24- or 32-bit integers, and bounded f16, f24, f32 or f64 values. Quantized scalars still have the Luau type number. Numeric formats
Roblox values
Send vectors, CFrames, Color3 and supported native types such as UDim, sequences, Font and DateTime. Quantized vectors keep their native type. Compact CFrames have separate position and rotation error bounds. Vector and CFrame precision · Native types
Strings and collections
Declare exact or minimum and maximum lengths for strings, buffers and collections. Build records with structs, arrays, maps, sets, enums, optional fields or tagged unions. Recursive schemas and unbounded buffers or maps are unsupported. Composable shapes · Bit packing
Instance references
Declare an allowed class with schema.Instance(className). The server owns the permitted scope. Each complete frame can carry up to 16 references across immediate, queued, unreliable, ordered or RPC payloads. Instance rules

The module exports Definition<S>, ServerSession<S>, ClientSession<S>, RelayError, Connection and RequestResult<T>. Event schemas

Batch or replace updates

For a single event, call Send. By default, reliable events with only primitive fields use native Roblox tuples. Unreliable and composite events use bounded buffers.

Keep every queued event
Use CreateBatch for one flush or CreateBatcher for repeated batches on queue-enabled events. A client's CreatePacedBatcher can split packets within limits and flush manually or on a timer. FIFO batches · Client pacing
Keep the latest pose
Use CreateState when a newer value for the same key may replace an unsent one. A server can defer updates for a captured audience under its outbound byte budget and let recipients make progress independently. State queues · Outbound budgets
Send to everyone
For the current roster, CreateBroadcastBatcher sends a shared packet on each channel with queued events. CreateBroadcastState shares the latest unsent values. Broadcast batches · Broadcast state
Stream a moving object
Eligible ordered server events can set a send rate, suppress unchanged samples and send a keepalive. Streams include server timestamps. Client events can declare timestampWindow for a server-time field that Relay fills at submission. Scheduled streams · Client timestamps

The state snapshots example uses a fixed audience and shows what happens when its queue fills.

Request a reply

Declare the request fields and response shape together. For a client request, connect the handler with server.requests.Name:Connect(handler). Call client.requests.Name:Request(timeoutSeconds, ...) and use Await() on the returned handle. Cancel() ends the local wait. Work already underway on the server can still finish.

The combat and inventory example combines event maps and requests an inventory response. Request API

Session API

Relay.VERSION
The library version.
Relay.schema
Construct field types and event definitions. Use schema.compose(...) to combine event maps.
Relay.define(spec)
Validate and freeze a shared definition.
Relay.inspect(definition)
Read compiled schema details and limits.
Relay.createServer(definition, options)
Create the server session with its required inboundRate limits.
Relay.createClient(definition, options)
Create the client session with a startup timeout.

Connect listeners before calling Start(). Fallible calls return a value or success flag and an error. Read the error's code and message when a call fails.

Call GetDiagnostics() to inspect a session. You can enable traffic counters and bounded refusal reports without changing the messages sent. Traffic and refusal reports

End a session

Each endpoint accepts one listener. Call connection:Disconnect() when it should stop receiving events. Cancel an open batch or destroy a state queue when you finish with it.

Call session:Destroy() to release the session. Repeating Disconnect() or Destroy() is safe. If the transport goes away, create a new session to reconnect.

Versions and source

Version 0.3.0 supports up to 64 endpoints, two-way requests with concurrency limits and refusals, and 22 bounded native Roblox value shapes. It adds RR7 unreliable frames for primitive payloads and RR8 ordered unreliable events. When changing a schema or topology, check compatibility before updating clients and servers. Upgrade compatibility

Version 0.1.0 introduced typed reliable and unreliable events, bounded schemas and server checks for incoming client traffic. Since 0.2.0, each release tag preserves its reference. Original source · 0.2.0 reference · Latest release
